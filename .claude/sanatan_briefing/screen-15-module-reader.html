Concept 2 of 5 · आत्मन्
Ātman — the self that observes.

The Upaniṣads draw a sharp line between the body, the mind, and the one who watches both. That watcher — eternal, unchanging, the same in every being — is called Ātman.

Ātman is not a soul in the Christian sense. It is not a piece of you that goes to heaven. It is the irreducible awareness that is reading these words right now.

What this screen covers

Module reader — chrome (consistent across all step types)

  • Topbar: ✕ close (left) + Module name in Lora italic saffron + counter "X / Y" in dText3 (right). Compact, doesn't compete with body.
  • Progress bar: 3px full-bleed saffron under topbar, animates 280ms easeOut when advancing. Matches your existing app's pattern.
  • Body container: Vertically centered in the available space. Padding 24px horizontal. Entire body is the tap target.
  • Tap hint: "Tap anywhere to continue" in 11px lowercase tracked sans-serif, dText3, 28px from bottom. Subtle — doesn't shout.
  • Step transition: Slide-in from right + fade (280ms). Previous step slides out left simultaneously. Same easing as a page route.

Five step types — each has its own typographic identity

  • INTRO / CONCEPT: Small-caps label (saffron) + 28px serif title in cream + 16px serif body in dText2. Used for framing, definitions, narrative connective tissue. Label can be "INTRODUCTION", "CONCEPT 2 OF 5 · आत्मन्", "RECAP", etc.
  • KEY VERSE: "KEY VERSE" pill in iron-red bright (8% tint, 1px border) — THE ONE PLACE OUTSIDE FESTIVALS where iron-red appears, because it's a "featured" semantic. 22px serif quote. Outlined saffron pill button "Read BG·2·20 in the Gītā" routes to verse detail.
  • REFLECT: Meditation/diya glyph (saffron-deep) + small-caps "Reflect" label + 22px serif question + italic "Sit with this question" footer. The diya icon replaces the generic Material meditation glyph from your live app — fits the heritage palette.
  • COMPLETE: Separate group below — see Module Complete.

Module Complete — why the green checkmark had to go

  • The problem: Your live app uses a green check inside a green circle. Green appears nowhere else in the app — palette is saffron, iron-red, cream. A foreign color on the success screen breaks the visual contract.
  • The fix: Saffron checkmark inside a small palm-leaf binding-line frame. The check itself is in saffron with a subtle text-shadow glow. The frame uses the BindingLine widget top and bottom (140px wide). Reads instantly as "success" because of the check, but speaks the language of the app.
  • "Module Complete" title: Lora 32px w500 in cream. Below: module name in 18px italic serif. Centered. Standard hero rhythm.
  • Hairline divider separates the celebration from the next-action surface (recommendations).

Continue learning — book recommendations redesigned

  • Kept this feature. External book recommendations are a real differentiator and you already have data populated. Just had to fit the aesthetic.
  • "RECOMMENDED FOR THIS MODULE" in small-caps saffron — uses the section label pattern from the rest of the app.
  • Book row: 48px square icon (1px dDivider border, saffron book glyph inside, 4px radius) + Lora serif title (15px w500) + italic serif author + external-link arrow. 12px vertical padding, 1px dDividerSoft separator.
  • Tap a row: Opens external URL (Amazon/Flipkart/publisher site) via url_launcher. The external-link arrow signals "leaves the app."
  • Primary CTA: Full-width "Back to Learning Path" in standard saffron pill (50px height, 28px radius, uppercase tracked). Pops to /practice.

Motion choreography

  • Step content entry: Ink-settle animation (fade up 6px) with 80-340-480ms stagger between label → title → body → footer. Echoes verse-detail entry.
  • Complete screen entry: Slow sequenced reveal — check leaf (100ms) → title (280ms) → module name (420ms) → divider (580ms) → recommend label (660ms) → book rows (720, 780ms) → button (920ms). Total ~1 second. Feels earned, not rushed.
  • Progress bar: Animates from previous-step width to current-step width over 280ms easeOut when step advances. Synced with step transition.

Data shape for Drift

  • enum ModuleStepType { intro, concept, keyVerse, reflect, complete }

class ModuleStep {
  final String id;
  final int stepIndex;           // 1-indexed
  final int totalSteps;
  final ModuleStepType type;
  final String? label;           // small-caps section label (optional)
  final String? title;           // hero title (intro/concept)
  final String body;             // main body text
  final String? verseRef;        // e.g. "BG/2/20" — keyVerse only
  final String? verseLabel;      // e.g. "Read BG·2·20 in the Gītā" — keyVerse only
}

class BookRecommendation {
  final String title;
  final String author;
  final String url;              // external link
  final String? coverAssetPath;  // optional; null = default book glyph
}

Don'ts

  • ❌ Don't add a "Continue" or "Next" button — tap-anywhere preserves the meditative flow of your live app.
  • ❌ Don't show step content top-aligned — vertically center it in the body area for visual calm.
  • ❌ Don't add green anywhere on Module Complete — saffron is the success color in this app.
  • ❌ Don't add confetti, badges, or celebration animations on Complete — restraint matches the voice.
  • ❌ Don't show iron-red on any step type other than KEY VERSE — it's reserved for festivals + destructive + featured-verse semantic only.
  • ❌ Don't render the meditation icon as Material Icons default — use the diya/lamp glyph so it speaks the heritage vocabulary.
